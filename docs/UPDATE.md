# 升级指南

## 1. 两种方式

| 方式 | 适用 | 做法 |
|---|---|---|
| UI 一键更新 | 有外网、使用官方发行版 | 「系统 → 更新」→ 检查 → 应用（失败自动回滚） |
| 手工替换 | 离线环境 | 下载新包 → 停服 → 替换 `bin/` 与文档 → 启动 |

> 升级前先备份：数据库 dump + `data/platform/`（见 `DEPLOYMENT.md` §6）。

## 2. 发行物与签名

每个 Release 包含：

```
kasama-<ver>-windows-amd64.zip
kasama-<ver>-linux-amd64.tar.gz
kasamastrike-<os>-<arch>[.exe]
manifest.json           # 版本矩阵（平台/运行时/数据库结构）
manifest.json.sig       # Ed25519 签名（平台内置公钥验签）
SHA256SUMS-<ver>.txt    # 人读校验
```

手工校验：

```bash
sha256sum -c SHA256SUMS-<ver>.txt
```

## 3. UI 一键更新会做什么

1. 读取 `manifest.json` 并**验签**（签名无效直接拒绝，不会“降级为只校验哈希”）；
2. 对比三方版本：平台 / 运行时 / 数据库结构（schema）；
3. 预检：磁盘、写权限、版本兼容区间（过低要求先升中间版本）；
4. 等当前任务收尾 → 备份二进制与数据库 → 替换 → 迁移 → 重启 → 健康检查；
5. 失败自动回滚到上一版本（数据库按备份恢复，可能丢失更新后的增量）。

## 4. 版本兼容规则

| 情况 | 结果 |
|---|---|
| 数据库结构比程序新 | 拒绝启动更新（提示先升级程序） |
| 平台版本低于 `min_upgrade_from` | 拒绝，要求先升到中间版本 |
| 运行时版本不同 | 允许单独升级运行时（无状态，可跨版本） |
| 回退需要恢复数据库 | 清单标 `rollback_safe=false`，UI 会二次确认 |

## 5. 离线升级

```bash
# 停服 → 备份 → 解压新包覆盖 bin/ 与 docs/
docker exec kasama-pg pg_dump -U kasama -Fc -d kasama -f /tmp/pre.dump
# 覆盖后启动；数据库迁移在启动时自动执行（失败会保留旧版本并拒绝启动）
```

## 6. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 检查更新报“签名校验失败” | 清单被篡改/下载不完整 | 重新下载；不要关闭校验 |
| 提示“清单缺失” | 该发行版未附 manifest | 手工升级；或等修复版 |
| 更新卡在“等待任务收尾” | 有长任务在跑 | 在任务页暂停，或等待其结束 |
| 启动后版本没变 | 没有守护进程拉起新进程 | 手工启动一次（`Kasama-Start.bat` / systemd） |
| 迁移失败 | 结构冲突 | 用更新前 dump 恢复，并反馈日志 |
